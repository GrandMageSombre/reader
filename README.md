# 墨读 · MoDuReader

一个**规则驱动**的 Android 小说阅读器：分类、书单、目录、正文全部由「书源 JSON」描述，
换站点只改配置、不改代码。

> **使用声明**：本项目为本地自用工具。应用**不内置、不代理、不分发**任何第三方站点内容；
> 书源由使用者自行编写与维护，内容的版权状态、可访问性由使用者自行判断。请勿用于商业用途或传播他人作品。

---

## 功能

| 模块 | 说明 |
|------|------|
| 书城 | 书源自带分类（对应站点自己的分类体系），分类下无限翻页；支持单书源搜索 |
| 书架 | 网格书架、封面、阅读进度百分比、继续阅读、移出书架、书籍详情 |
| 阅读器 | 上下滚动阅读，**字号 13–34 可调**、**行距 / 段距可调**、**宋体 / 黑体 / 默认字体**、**白 / 米黄 / 护眼 / 夜间四套配色**、亮度调节、阅读时常亮 |
| 目录 | 全本章节目录，当前章高亮，点击直达 |
| 进度 | 记住「第几章 + 滚动位置」，退出重进自动回到原位 |
| 缓存 | 章节正文、目录落 SQLite；离线可看已读章节，正文缓存优先（翻回去不重复请求） |
| 抓全 | **目录 / 正文分页拼接**：`chapterUrl` 的 `{page}`、`chapterNext`、`contentNext` 三种规则把分页抓齐；正文散在多个容器时按文档顺序自动合并 |
| 书源 | 导入 / 删除 / 启停 JSON 书源，剪贴板粘贴导入，一键复制模板；内置示例源不可删 |
| 全站爬取 | 配套 `tools/spider`（PC 端 Python）：抓起点/番茄的书目、目录、正文落 SQLite，经本地接口喂给阅读器；番茄正文做**字体反混淆** |

## 书源规则引擎

一个书源就是一份 JSON（完整字段与语义见 [`docs/书源规则.md`](docs/书源规则.md)）：

```json
{
  "id": "my_source",
  "name": "我的书源",
  "baseUrl": "https://example.com",
  "categories": [{ "name": "玄幻", "url": "/list/xuanhuan/{page}.html" }],
  "rules": {
    "listItem": ".book-list li",
    "listName": "h3 a@text",
    "listLink": "h3 a@href",
    "chapterList": "#list dd a",
    "chapterName": "text",
    "chapterLink": "href",
    "content": "#content",
    "contentClean": ["script", ".ad", "re:本章未完"]
  }
}
```

规则写法 `CSS选择器@取值`，取值支持 `text` / `ownText` / `html` / `href` / `src` / `attr:xxx` / `abs:href`；
省略 `@` 即按取文本处理；只写 `text`、`href` 表示对「当前节点自己」取值（章节列表逐项取值的写法）。

**只拿到一部分章节 / 半章正文**时，靠这几个字段补全（详见 [`docs/书源规则.md`](docs/书源规则.md)）：

```json
{
  "rules": {
    "chapterUrl": "/book/1/",                     // ① 目录不在详情页：指向真正的目录页
    "chapterNext": "div.pager a.next@href",       // ② 目录本身分页：跟着「下一页」链接翻
    "contentNext": "a:contains(下一页)@href",      // ③ 一章被拆成 /1.html、/2.html：拼完整
    "content": "#content, #content2"              // ④ 正文散在多个容器：按文档顺序合并
  }
}
```

> ① 也可写成带页码的模板 `"chapterUrl": "/book/1/{page}.html"`（page 从 1 开始，抓到空页为止），
> 与 ② 二选一。单章最多拼 10 页、目录最多翻 20 页；抓到空页、重复页或下一页取不到就自动停下。

**关于起点 / 番茄**：这两个站点的正文接口有请求签名、加密字体和付费章节，
本项目**不提供**绕过这些机制的规则或代码。你要接它们，只能接你有权访问的部分（例如自有账号可访问的公开页），
规则自己写在书源 JSON 里；引擎本身对站点无感知。

## 技术栈

- Kotlin + Jetpack Compose（Material 3），单 Activity + Navigation Compose
- 抓取：`HttpURLConnection` + Jsoup，无 OkHttp / 无 Retrofit
- 存储：系统 `SQLiteOpenHelper`（书架 / 目录 / 正文）+ `SharedPreferences`（阅读设置）
- 依赖极简：只有 Jsoup 与 Coil（封面），没有注解处理器、没有 Room / Hilt

```
app/src/main/java/com/modu/reader/
├── App.kt                     # Application：初始化设置、数据库、书源、仓库
├── MainActivity.kt
├── data/                      # Models / Db / SettingsStore
├── net/Http.kt                # 极简 HTTP + 编码识别（gbk/utf-8）
├── source/
│   ├── SourceConfig.kt        # 书源 JSON 模型与解析
│   ├── Rule.kt                # 规则求值 + 正文按块拆段
│   ├── BookSource.kt          # 书源能力接口（接自建后端只需实现它）
│   ├── HtmlSource.kt          # 规则驱动的实现
│   ├── LocalLibrarySource.kt   # 读 PC 爬虫库（tools/spider 的本地 JSON 接口）
│   ├── DemoSource.kt          # 内置公版示例源
│   └── SourceManager.kt       # 导入 / 删除 / 启停
├── repo/BookRepo.kt           # 书源 + 缓存 + 书架
└── ui/                        # shelf / browse / detail / reader / settings
```

配套的 PC 端爬虫在 `tools/spider/`（Python，见 [`docs/全站爬取.md`](docs/全站爬取.md)），
不属于 Android 模块，不参与 APK 构建。

## 换源阅读（起点 / 番茄 → 采集站）

**为什么需要这个**：起点 VIP 章节只给试读片段，番茄正文页由 JS 渲染抓不到。
同一本书通常在第三方采集站有全本——所以本项目的做法是：

```
起点/番茄  ──按平台官方分类──►  书名/作者/简介/封面
                                    │
                                    │ 点「换源阅读」（按书名在采集站里搜）
                                    ▼
                          采集站（多镜像容错）──►  完整目录 + 正文
```

### 书城只有两个入口

按需求，**书城首页只展示「起点中文」和「番茄小说」**（`BuiltinSources.STOREFRONT_IDS`）。
它们负责按各平台自己的分类发现书；采集站不作为入口出现，只在换源时干活。

采集站仍可在「设置 → 书源管理」里单独启用/停用，也支持导入更多。

起点分类 id 要从 `https://m.qidian.com/category/` 导航取。实测**每类只给出 5 本书**，
分类页分页参数（`?page=2`、`/page2/`、`/2/`）**全部无效**——站点限制，不是漏抓。

### 番茄：按书自带的官方分类归类

番茄**没有任何「按分类列书」的接口**，实测：

| 尝试 | 结果 |
|------|------|
| HTML 首页 | 完全 JS 渲染，`__NEXT_DATA__` 里也没书籍数据 |
| `/api/rank/list?type=N` | 只有 **type = 0/1/2** 有数据，共 **26 本** |
| `page` / `gender` / `category_id` / `dim` / `app_id` 等参数 | **全部无效**，结果一模一样 |
| `/api/category/list`、`/api/book/category`、`/api/book/recommend` | 全部 404 |
| 书籍页相关推荐 | 没有，无法扩池 |

但**每本书自带官方三级分类**（`/api/book/info` 的 `category` 字段）：

```
《偏偏世子要娶我》 → 女生/古代言情/宫闱宅斗
《人生三十》       → 男生/都市/都市生活
《都市至尊战神》   → 男生/都市/都市生活
```

所以做法是：把三档榜单 26 本全抓下来，**按书自身的官方分类归组**。
每本书要多一次 `book/info` 请求，结果缓存 30 分钟。

实测分布：`男生/都市` **15 本**，其余分散在玄幻/仙侠/历史/科幻/武侠/奇幻/职场/女生言情。
**番茄每类书会很少，这是番茄自身的数据上限。**

### 采集站：多镜像容错

一个采集站书源内部持有一组镜像（`BiqugeMultiSource`）：

1. 换源时依次在所有镜像上按书名搜索，谁能搜到用谁；
2. 抓正文失败自动换下一个镜像（用「书名 + 同章标题」对齐章节）；
3. 用户不需要知道哪个站在干活。

**实测 12 个候选采集站，只有 2 个能用**：

| 站点 | 对番茄 26 本的覆盖 | 说明 |
|------|-------------------|------|
| 望书网 | **8 / 26** | 主站，目录可到 1000+ 章 |
| 2K 小说 | 6 / 26 | 可作备用镜像 |
| 八一中文 | 搜索 ConnectionReset | 与望书网同站群 |
| 31xs / 91zww | 0 / 26 | 搜索页只有「热门推荐」，不是真结果 |
| 其余 6 个 | 搜索 404 | 无可用静态搜索接口 |

### 真实覆盖率（请知悉）

端到端实测番茄「男生/都市」15 本：

```
✅ 最强龙婿        53 章    正文 2752 字
✅ 极品全才神婿  1034 章    正文 2599 字
✅ 都市至尊战神    211 章    正文 2748 字
✅ 最强废婿       199 章    正文 4692 字
✅ 至尊女婿       296 章    正文 1733 字
✅ 人生三十      1066 章    正文 1832 字
✅ 最强弃子         3 章    正文 2287 字
✗  其余 8 本      采集站无收录
─────────────── 7 / 15 可读
```

**为什么不是 100%**：采集站库存是**已完结、较热的老书**，而起点/番茄榜单首页是**新书**。
新书还没被搬运，这不是代码能解决的。搜不到时换源面板会说明原因并给替代办法。

> 反过来看：目标书若是已完本的热门书（如《大奉打更人》），命中率很高——
> 实测 1027 章目录、正文完整。

### 用法

1. 书城选「起点中文」「番茄小说」或「手机直抓」，点一个分类 → 看到书单（番茄按官方分类）；
2. 点书进详情页 → 点 **「换源阅读」**；
3. 面板列出采集站搜到的同名/相近书（标「同名」的精确匹配）；
4. 选一个 → 目录和正文切到那个源；之后点「已换源 · 点击更换」可换或取消。

进度按**原书**记录，换源后读到哪一章不会丢。

### 匹配规则

| 情况 | 得分 |
|------|------|
| 书名完全相同 + 作者也对上 | 120 |
| 书名完全相同 | 100（标「同名」） |
| 一方包含另一方 + 作者对上 | 70 |
| 一方包含另一方 | 60（标「相近」） |


## 全站爬取（本地爬虫库）

换源是「拿第三方站点的正文」，而**全站爬取**是另一条路：直接把起点/番茄的书目、
目录、正文抓到本机，再让阅读器读本地库。抓取的活全部在电脑上跑，手机只读一个 JSON 接口。

```
起点 / 番茄 ──tools/spider──► data/library.db ──serve──► http://<电脑IP>:8765
                                                              │
                                              书源「本地爬虫库」（可选，要连 PC）
```

> **不想连 PC？** 书城里有「**手机直抓**」内置书源：它用 App 内的隐藏 WebView
> 过一次反爬，直接在手机上抓起点书库（15 个分类）与番茄榜单的目录正文，
> 不用跑 `serve.py`、不用填 IP。想铺全站（十几万册）再用 PC 那条路。

```bash
pip install -r tools/spider/requirements.txt
python -m tools.spider.cli qidian-catalog --filters 15 --pages 10   # 起点书库
python -m tools.spider.cli qidian-chapters --limit 60              # 目录
python -m tools.spider.cli qidian-content --limit 400              # 正文
python -m tools.spider.cli fanqie-all --limit 900                  # 番茄一条龙
python -m tools.spider.cli serve --port 8765                        # 给阅读器读
```

实测要点（细节见 [`docs/全站爬取.md`](docs/全站爬取.md)）：

| 站点 | 关键结论 |
|------|----------|
| 起点 | PC 站裸请求返回 **202 + `probe.js`** 指纹页；用 headless Edge 过一次拿 cookie 后，书库 `/all/`（每页 20 本、`data-pagemax=50`、实测 **137 个筛选**）、书籍页全量目录、`main[id^=c-]` 正文都是纯 HTTP 可取 |
| 起点 VIP | 只给约 130 字试读，入库标 `vip_preview`，阅读器里章名后加「（试读）」 |
| 番茄 | 没有按分类列书的接口，书池就是榜单 **26 本**；目录走 `/api/reader/directory/detail`，一部长生不可期 3497 章可全拿 |
| 番茄正文 | 每个字都被换成私有区码位，靠 `@font-face` 子集字体渲染。子集 = **SourceHanSansSC-Normal 2.002R** 的原样轮廓，用同版字体建「轮廓哈希 → 真字」表后可 **362/362 精确还原** |

进「本地爬虫库」前记得改 `baseUrl`：默认 `http://127.0.0.1:8765` 只对本机有效，
手机要填电脑的局域网 IP（`设置 → 书源管理 → 本地爬虫库`）。

不打算连 PC 的话，这条可以完全不管：书城里的「手机直抓」已经能在 App 内独立跑。

## 付费墙与手机端抓取

先说结论（实测，见 [`docs/付费墙与换源.md`](docs/付费墙与换源.md)）：

| 站点 | 未付费时服务端给什么 | 能不能技术绕过 |
|------|----------------------|----------------|
| 起点 VIP | 约 130 字试读 +「订阅本章」 | 不能：HTML 里没有后文 |
| 番茄付费章 | 空正文 / `preview` 短片段 | 不能：`__INITIAL_STATE__` 里就没有 |
| 番茄 App 接口 | 无签名 → 404 / 空响应 | 要逆向 native libsign，成本极高且易失效 |

能落地的三条路，都已经接进 App：

1. **本机抓取**（详情页按钮，只在起点/番茄出现）：隐藏 WebView 跑一遍页面过掉
   `probe.js` / 验证码中间页 → 拿 cookie → 直接抓目录与正文写进本地缓存。
   番茄正文用**内置字形表**还原（`assets/fanqie_glyphs.json`，362 条），
   所以手机上不需要 PC，也不用解析 woff2。
2. **账号态**：`WebGate.loginCookie()` 用 WebView 打开站点，你自己登录后取回 cookie，
   已订阅的章节就是全文（账号密码不落盘）。
3. **付费章自动换源**：抓到试读/空正文时，自动去采集站按「书名 + 章名」捞正文，
   同名章按预期位置纠偏。实测（望书网，抽样 12 章）：全职法师 11/12、
   仙人消失之后 11/12、修真聊天群 11/12、凡人修仙传 11/12，VIP 章正文 1172–3379 字。

所以：**手机抓你在看的那几本，PC 铺全站，VIP 章走换源**。

> **关于付费与反爬**：本项目不实现任何绕过付费墙、请求签名、验证码、字体加密的逻辑。
> 起点 VIP 章节只拿到站点本身给出的试读片段；番茄与微信读书只到公开页面能读的部分。

## 第三方书源（Legado / 「阅读」格式）

除了自己写 JSON，也能直接导入社区里的第三方书源。**想看更多书源，去这几个源仓库挑**：

| 来源 | 地址 | 说明 |
|------|------|------|
| 源仓库 | <https://www.yckceo.com/yuedu/shuyuan> | 国内最大的「阅读」书源索引，按可用性排序 |
| Yiove 综合书源库 | <https://shuyuan.yiove.com/complex> | 多源聚合，带分组 |
| XIU2/Yuedu | `https://cdn.jsdelivr.net/gh/XIU2/Yuedu@master/shuyuan` | GitHub 12k+ star，数组格式，可整份导入 |
| aoaostar/legado | `https://cdn.jsdelivr.net/gh/aoaostar/legado@release/sources/` | 按 hash 分文件，里面混有 TTS 源，需筛选 |

导入方式：在「书源管理 → 导入」里直接粘贴 JSON（单个书源或数组都可以），应用会自动识别格式。

> 本项目实测过一批社区源（约 270 个候选、200 个站点）：**大部分站点拿不到可用的分类书单**，
> 因为它们是 JS 渲染、或需要登录、或分类路径与规则对不上。
> 内置的「三一小说 / 望书网」就是这样从书源合集里筛出来、并逐层验证过三层（分类→目录→正文）的。

转换规则只做**能等价翻译的子集**：

| Legado 写法 | 转换结果 |
|-------------|----------|
| `class.item` | `[class*=item]` |
| `id.list@tag.a` | `#list a` |
| `tag.a@href` / `tag.p@text` | `a@href` / `p`（text 是默认取值，可省略） |
| 尾部 `##正则` | 丢弃（本引擎的清理走 `contentClean`） |
| 纯 GET 的 `searchUrl`，`{{key}}` / `{{page}}` | `{key}` / `{page}` |

**不转换**（字段留空，并在书源卡片的备注里写明）：`@js:` / `<js>` 脚本、XPath（`//...`）、
POST 请求体、`tag.p.1` 这类**同级别索引**（Legado 的 `.1` 与 CSS `:nth-of-type` 语义不同，硬译会取错节点）。
所以社区书源里带 JS 的往往只能部分可用——这是能力边界，不是 bug。

## 未做 / 已知限制

- 阅读器是**上下滚动**模式，没有做仿真翻页（分页测量与手势需要另一套渲染管线）
- 目录 / 正文分页拼接要自己在书源里配规则（`chapterUrl` 的 `{page}`、`chapterNext`、`contentNext`），
  引擎不去猜站点的翻页规律
- 番茄 / 微信读书的正文页依赖 JS 渲染，内置源只取公开的书籍信息与目录
  （要读番茄正文，用 `tools/spider` 抓成本地库，走「本地爬虫库」）
- 第三方 Legado 书源里的 JS / XPath / POST 规则不转换，相关功能留空
- 社区书源大部分站点不可用（JS 渲染 / 需登录 / 分类路径对不上），内置源只收录逐层验证过的
- 书源自检还没做（导入后要在书城里点一次才知道规则对不对）
- 搜索只搜当前书源，没有跨源聚合搜索
