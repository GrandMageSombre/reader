# 墨读 · MoDuReader

一个**规则驱动**的 Android 小说阅读器：分类、书单、目录、正文全部由「书源 JSON」描述，
换站点只改配置、不改代码。

> **使用声明**：本项目为本地自用工具。应用**不内置、不代理、不分发**任何第三方站点内容；
> 书源由使用者自行编写与维护，内容的版权状态、可访问性由使用者自行判断。请勿用于商业用途或传播他人作品。

---

## 功能

| 模块 | 说明 |
|------|------|
| 书城 | 书源自带分类（对应站点自己的分类体系），分类下无限翻页；支持单书源搜索 |
| 书架 | 网格书架、封面、阅读进度百分比、继续阅读、移出书架、书籍详情 |
| 阅读器 | 上下滚动阅读，**字号 13–34 可调**、**行距 / 段距可调**、**宋体 / 黑体 / 默认字体**、**白 / 米黄 / 护眼 / 夜间四套配色**、亮度调节、阅读时常亮 |
| 目录 | 全本章节目录，当前章高亮，点击直达 |
| 进度 | 记住「第几章 + 滚动位置」，退出重进自动回到原位 |
| 缓存 | 章节正文、目录落 SQLite；离线可看已读章节，正文缓存优先（翻回去不重复请求） |
| 抓全 | **目录 / 正文分页拼接**：`chapterUrl` 的 `{page}`、`chapterNext`、`contentNext` 三种规则把分页抓齐；正文散在多个容器时按文档顺序自动合并 |
| 书源 | 导入 / 删除 / 启停 JSON 书源，剪贴板粘贴导入，一键复制模板；内置示例源不可删 |

## 书源规则引擎

一个书源就是一份 JSON（完整字段与语义见 [`docs/书源规则.md`](docs/书源规则.md)）：

```json
{
  "id": "my_source",
  "name": "我的书源",
  "baseUrl": "https://example.com",
  "categories": [{ "name": "玄幻", "url": "/list/xuanhuan/{page}.html" }],
  "rules": {
    "listItem": ".book-list li",
    "listName": "h3 a@text",
    "listLink": "h3 a@href",
    "chapterList": "#list dd a",
    "chapterName": "text",
    "chapterLink": "href",
    "content": "#content",
    "contentClean": ["script", ".ad", "re:本章未完"]
  }
}
```

规则写法 `CSS选择器@取值`，取值支持 `text` / `ownText` / `html` / `href` / `src` / `attr:xxx` / `abs:href`；
省略 `@` 即按取文本处理；只写 `text`、`href` 表示对「当前节点自己」取值（章节列表逐项取值的写法）。

**只拿到一部分章节 / 半章正文**时，靠这几个字段补全（详见 [`docs/书源规则.md`](docs/书源规则.md)）：

```json
{
  "rules": {
    "chapterUrl": "/book/1/",                     // ① 目录不在详情页：指向真正的目录页
    "chapterNext": "div.pager a.next@href",       // ② 目录本身分页：跟着「下一页」链接翻
    "contentNext": "a:contains(下一页)@href",      // ③ 一章被拆成 /1.html、/2.html：拼完整
    "content": "#content, #content2"              // ④ 正文散在多个容器：按文档顺序合并
  }
}
```

> ① 也可写成带页码的模板 `"chapterUrl": "/book/1/{page}.html"`（page 从 1 开始，抓到空页为止），
> 与 ② 二选一。单章最多拼 10 页、目录最多翻 20 页；抓到空页、重复页或下一页取不到就自动停下。

**关于起点 / 番茄**：这两个站点的正文接口有请求签名、加密字体和付费章节，
本项目**不提供**绕过这些机制的规则或代码。你要接它们，只能接你有权访问的部分（例如自有账号可访问的公开页），
规则自己写在书源 JSON 里；引擎本身对站点无感知。

## 技术栈

- Kotlin + Jetpack Compose（Material 3），单 Activity + Navigation Compose
- 抓取：`HttpURLConnection` + Jsoup，无 OkHttp / 无 Retrofit
- 存储：系统 `SQLiteOpenHelper`（书架 / 目录 / 正文）+ `SharedPreferences`（阅读设置）
- 依赖极简：只有 Jsoup 与 Coil（封面），没有注解处理器、没有 Room / Hilt

```
app/src/main/java/com/modu/reader/
├── App.kt                     # Application：初始化设置、数据库、书源、仓库
├── MainActivity.kt
├── data/                      # Models / Db / SettingsStore
├── net/Http.kt                # 极简 HTTP + 编码识别（gbk/utf-8）
├── source/
│   ├── SourceConfig.kt        # 书源 JSON 模型与解析
│   ├── Rule.kt                # 规则求值 + 正文按块拆段
│   ├── BookSource.kt          # 书源能力接口（接自建后端只需实现它）
│   ├── HtmlSource.kt          # 规则驱动的实现
│   ├── DemoSource.kt          # 内置公版示例源
│   └── SourceManager.kt       # 导入 / 删除 / 启停
├── repo/BookRepo.kt           # 书源 + 缓存 + 书架
└── ui/                        # shelf / browse / detail / reader / settings
```

## 换源阅读（起点 / 番茄 → 第三方源）

**为什么需要这个**：起点 VIP 章节只给试读片段，番茄正文页由 JS 渲染抓不到。
但同一本书通常在第三方源有全本——所以本项目的做法是：

```
起点/番茄  ──按分类发现──►  书名/作者/简介/封面
                                │
                                │ 点「换源阅读」（按书名在其它书源里搜）
                                ▼
                        第三方书源 ──►  完整目录 + 正文
```

两个角色在代码里是显式区分的：

| 角色 | 书源 | 实现 |
|------|------|------|
| **发现源**（只发现书） | 起点中文、番茄小说 | 实现 `DiscoverySource` 标记接口；换源时自动跳过它们 |
| **正文源**（提供目录/正文） | 三一小说、望书网、古登堡 等 | 普通 `HtmlSource` |

### 番茄怎么取列表？

番茄的 HTML 首页里书籍全在 `__NEXT_DATA__`，分页是 JS，CSS 规则抓不到。
但它有个可用的 JSON 接口：

```
GET https://fanqienovel.com/api/rank/list?type={0|1|2}
→ { "data": { "list": [{ bookId, bookName, author, abstract, thumbUri }] } }
```

实测（2026-10）：只有 `type` = 0/1/2 有数据，每类 7~10 本，**`page` 参数无效**（第 1 页与第 2 页内容相同）。
所以番茄书源对应「热榜一/二/三」三个分类、没有翻页——这也是为什么正文必须靠换源。

### 用法

1. 书城顶部选「起点中文」或「番茄小说」，点一个分类 → 看到书单；
2. 点书进详情页 → 点 **「换源阅读」**；
3. 面板里会列出在其它书源搜到的同名/相近书（标「同名」的是精确匹配）；
4. 选一个 → 目录和正文就切到那个源了，之后再点「已换源 · 点击更换」可以换别的或取消。

进度按**原书**记录，所以换源后读到哪一章不会丢。

### 匹配规则

| 情况 | 得分 |
|------|------|
| 书名完全相同 + 作者也对上 | 120 |
| 书名完全相同 | 100（面板里标「同名」） |
| 一方包含另一方 + 作者对上 | 70 |
| 一方包含另一方 | 60（面板里标「相近」） |

只返回得分 > 0 的候选。默认只显示「同名」，可以展开看「相近」结果。

### 命中率实况

实测番茄热榜前 4 本的换源结果：**4/4 精确命中**（都能在望书网找到同名书并读到正文，例如
《最强龙婿》→ 53 章、正文 3170 字）。

但起点分类页的**新书**在第三方源往往还没收录，实测 0/3。这不是 bug：
第三方聚合站收的是已完本/较热的书。搜不到时面板会明确提示。

## 内置示例源

「示例书库」不联网，内容为公版古典名著节选（西游记 / 红楼梦 / 三国演义 / 水浒传 / 唐诗 / 古文观止 /
聊斋 / 论语），用于验证书架、分类、翻章、字号主题切换等全部交互。删不掉，也不涉及任何版权内容。

## 内置书源

除示例书库外，还内置了 7 个真实站点。全部规则都用线上真实页面核对过
（fixture 在 `app/src/test/resources/fixtures`，回归测试 `BuiltinSourceRulesTest`）。
内置源**不能删除，但可以在「设置 → 书源管理」里自己勾选启用/停用**。

| 书源 | 能拿到 | 拿不到 | 默认 |
|------|--------|--------|------|
| 示例书库 | 本地公版节选，完全离线 | — | ✅ 开 |
| 三一小说（31xs） | 6 个分类书单、详情、**完整目录**、**正文全文** | — | ✅ 开 |
| 古登堡计划 | 中文公版书，**全文可读** | — | ✅ 开 |
| 望书网 | 7 个分类、目录（实测 240+ 章）、正文、**站内搜索** | — | 关 |
| 起点中文（`m.qidian.com`） | 8 个分类书单、详情、**完整目录**、免费章节正文 | VIP 正文（只给试读片段）、站内搜索 | 关 |
| 豆瓣图书 | 8 个标签书单，书名/作者/出版社/评分/简介/封面 | 正文（豆瓣不提供） | 关 |
| 番茄小说 | 书籍页的书名/作者/封面/状态 | 分类书单、正文（需 JS 渲染） | 关 |
| 微信读书 | 分类书单里的书名与封面 | 目录、正文（需登录态） | 关 |

> **为什么有的默认关闭？** 第三方聚合站的可用性与版权状态差异很大，不适合默认替用户打开。
> 默认只开「本地示例库 + 三一小说 + 公版古登堡」，其余在书源管理页里自己勾选；
> 顶部还有一个「全部启用」按钮，一次全开。

> **关于付费与反爬**：本项目不实现任何绕过付费墙、请求签名、验证码、字体加密的逻辑。
> 起点 VIP 章节只拿到站点本身给出的试读片段；番茄与微信读书只到公开页面能读的部分。

## 第三方书源（Legado / 「阅读」格式）

除了自己写 JSON，也能直接导入社区里的第三方书源。**想看更多书源，去这几个源仓库挑**：

| 来源 | 地址 | 说明 |
|------|------|------|
| 源仓库 | <https://www.yckceo.com/yuedu/shuyuan> | 国内最大的「阅读」书源索引，按可用性排序 |
| Yiove 综合书源库 | <https://shuyuan.yiove.com/complex> | 多源聚合，带分组 |
| XIU2/Yuedu | `https://cdn.jsdelivr.net/gh/XIU2/Yuedu@master/shuyuan` | GitHub 12k+ star，数组格式，可整份导入 |
| aoaostar/legado | `https://cdn.jsdelivr.net/gh/aoaostar/legado@release/sources/` | 按 hash 分文件，里面混有 TTS 源，需筛选 |

导入方式：在「书源管理 → 导入」里直接粘贴 JSON（单个书源或数组都可以），应用会自动识别格式。

> 本项目实测过一批社区源（约 270 个候选、200 个站点）：**大部分站点拿不到可用的分类书单**，
> 因为它们是 JS 渲染、或需要登录、或分类路径与规则对不上。
> 内置的「三一小说 / 望书网」就是这样从书源合集里筛出来、并逐层验证过三层（分类→目录→正文）的。

转换规则只做**能等价翻译的子集**：

| Legado 写法 | 转换结果 |
|-------------|----------|
| `class.item` | `[class*=item]` |
| `id.list@tag.a` | `#list a` |
| `tag.a@href` / `tag.p@text` | `a@href` / `p`（text 是默认取值，可省略） |
| 尾部 `##正则` | 丢弃（本引擎的清理走 `contentClean`） |
| 纯 GET 的 `searchUrl`，`{{key}}` / `{{page}}` | `{key}` / `{page}` |

**不转换**（字段留空，并在书源卡片的备注里写明）：`@js:` / `<js>` 脚本、XPath（`//...`）、
POST 请求体、`tag.p.1` 这类**同级别索引**（Legado 的 `.1` 与 CSS `:nth-of-type` 语义不同，硬译会取错节点）。
所以社区书源里带 JS 的往往只能部分可用——这是能力边界，不是 bug。

## 未做 / 已知限制

- 阅读器是**上下滚动**模式，没有做仿真翻页（分页测量与手势需要另一套渲染管线）
- 目录 / 正文分页拼接要自己在书源里配规则（`chapterUrl` 的 `{page}`、`chapterNext`、`contentNext`），
  引擎不去猜站点的翻页规律
- 番茄 / 微信读书的正文页依赖 JS 渲染，内置源只取公开的书籍信息与目录
- 第三方 Legado 书源里的 JS / XPath / POST 规则不转换，相关功能留空
- 社区书源大部分站点不可用（JS 渲染 / 需登录 / 分类路径对不上），内置源只收录逐层验证过的
- 书源自检还没做（导入后要在书城里点一次才知道规则对不对）
- 搜索只搜当前书源，没有跨源聚合搜索
