# 墨读 代码审查报告（第 3 轮 · 换源阅读：起点/番茄发现 + 第三方源正文）

> 流程：需求 → 实测站点真实结构 → 实现 → 联网全链路验证 → 四视角自审 → 修复 → 复测
> 日期：2026-10-29 · 需求：分类里能选起点和番茄，按对应网站分类抓书，
> 正文由第三方网站搜索显示（参考 vckai/novel、xinjiayu/NovelServer 的采集架构）

## 一、本轮改动

### 架构：发现源 / 正文源分离

用户要的效果本质是「换源阅读」。实现上把书源分成两种角色：

| 角色 | 书源 | 机制 |
|------|------|------|
| 发现源 | 起点中文、番茄小说 | 实现 `DiscoverySource` 标记接口，只提供分类发现；换源时自动跳过 |
| 正文源 | 三一小说、望书网、古登堡等 | 普通 `HtmlSource`，提供目录与正文 |

新增 `SwapMatcher`（按书名+作者打分匹配）、`swap` 表（记录映射）、`SwapDialog`（选择面板）。
阅读进度仍按**原书**记，换源只改变正文去哪里取。

### 实测驱动的三项关键修正

| 项 | 实测结论 | 处理 |
|----|----------|------|
| 番茄列表 | HTML 首页书全在 `__NEXT_DATA__`、分页是 JS；但 `/api/rank/list?type=N` 返回 JSON（type 仅 0/1/2 有效，每类 7~10 本，`page` 参数无效） | 新写 `FanqieSource` 走 JSON，分类=三个热榜 |
| 起点分类 id | 凭猜测写的 `catid23/24/25/27/31/32` **全部 404**；实测可用的是 21,1,2,22,4,5,6,7,8,9,10,12,15 | 按 `m.qidian.com/category/` 的真实导航重配 13 个分类 |
| 第三方源搜索 | 望书网搜索页是 `table.grid tr#nr` 表格，与分类页 `div.item` 卡片结构完全不同 | 新增 `search*` 规则组，让搜索页单独配置 |

### 新增能力：`search*` 规则组

`SourceRules` 增加 `searchItem / searchName / searchLink / searchAuthor / searchCover / searchIntro`，
留空则复用 `list*`。这是换源能工作的前提（换源靠按书名搜索）。

```

② 换源：候选 5 个，同名 1 个 → 望书网 http://www.wangshuwx.com/44_44348/
```

属预期行为，面板会明确提示「没有在其它书源里搜到这本书」。

## 五、遗留

- 番茄接口分页无效，分类容量小（服务端限制）；
- 换源命中率受第三方站收录影响，无解，只能多启用几个正文源；
- 起点站内搜索是 JS 挑战页，发现源不支持搜索（靠第三方源搜）；
- `swap` 表只记一本书的单个映射，暂不支持「多源对比择优」。
