# 墨读 代码审查报告（第 2 轮 · 抓全资源与内置书源）

> 流程：需求实测 → 逐层验证真实站点 → 四视角审查 → 回读源码核实 → 当场修复 → 复测
> 日期：2026-10-29 · 需求：①获取完整的章节资源 ②内置多个书源 ③内置源由用户自己选择 ④支持第三方书源

## 一、本轮改动

### 1. 抓全资源（v1.1.0 起）

问题：站点把一章拆成 `/1.html`、`/2.html`，或正文散在多个容器里时，只拿到第一页/第一块。

| 新增能力 | 实现 |
|----------|------|
| 目录独立地址 | `chapterUrl` 支持三种写法：留空=详情页 / URL 或 `{page}` 模板 / `选择器@href` 从详情页取 |
| 目录分页拼接 | `chapterUrl` 的 `{page}` 模板，或 `chapterNext` 跟「下一页」链接 |
| 正文分页拼接 | `contentNext` 跟「下一页」链接，单章最多 10 页 |
| 正文多容器合并 | `content` 匹配多个容器时按文档顺序合并，`outermost()` 去掉嵌套命中 |

### 2. 内置书源（v1.2.0 → v1.3.0）

从 GitHub 的 Legado 书源合集（aoaostar/legado、XIU2/Yuedu）取样 **274 个候选**，
实测 **202 个站点**，最终只有**逐层验证通过**的站点进入内置：

| 内置源 | 验证结果 |
|--------|----------|
| 三一小说（31xs） | 分类 6 本/页、目录 35+ 章、正文 165 段 ✅ |
| 望书网（wangshuwx） | 分类 6 本/页、目录 242 章、正文可读 ✅ |
| 起点中文（m.qidian.com） | 详情/目录 171 章/免费章正文 ✅ |
| 豆瓣图书 | 标签书单 20 本、详情元信息 ✅ |
| 古登堡计划 | 中文公版书全文 ✅ |
| 番茄小说 | 仅书籍页（正文需 JS） |
| 微信读书 | 仅书单页（正文需登录） |

### 3. 内置源用户自选

- `BuiltinSources.DEFAULT_ON` 只放「本地示例库 + 三一小说 + 公版古登堡」；
- 其余内置源默认关闭，用户在书源管理页自己勾选；
- 开关状态落 `.builtin-disabled` / `.builtin-enabled` 两个文件；
- 书源管理页顶部有「全部启用」按钮。

### 4. 第三方书源导入

新增 `LegadoImporter`：把 Legado 格式转成本引擎的 CSS 规则，只做能**等价翻译**的子集，
不能转的字段留空并在 `skipped` 里说明原因。

## 二、审查发现与处置

### P0（已修）

| # | 位置 | 问题 | 后果 | 修复 |
|---|------|------|------|------|
| 1 | Rule.kt:34 `split()` | 用 `lastIndexOf('@')` 找取值分隔符，`meta[property='og:image']@content` 会从引号中间劈开 | 所有用属性选择器的详情页规则静默失效（书名/作者/封面全空） | 新增 `lastAtOutsideQuotes()`，只在引号外找 `@` |

## 三、误报澄清

| 子智能体结论 | 核实结果 |
|--------------|----------|
| 「`listName` 转换后丢了 `bookList` 前缀，是 bug」 | **误报**。`listName` 是相对 `bookList` 项求值的，本引擎与 Legado 语义一致，不该带前缀。是测试预期写错，已改测试 |
| 「`tag.p@text` 转换后变成 `p`，丢了 `@text`」 | **误报**。`text` 是本引擎默认取值，省略等价。非 text 取值（`@src` 等）经验证会保留 |
