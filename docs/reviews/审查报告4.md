# 墨读 代码审查报告（第 4 轮 · 书城只留起点/番茄 + 番茄按官方分类 + 多镜像容错）

> 流程：需求 → 逐项实测平台真实能力 → 实现 → 联网端到端验证 → 自审 → 修复 → 复测
> 日期：2026-10-29 · 需求：①书城点进去只有起点、番茄两个入口
> ②按对应 app 的分类把书分类展示 ③尽量爬全章节，爬不到的多个采集站确保能读完

## 一、本轮改动

### 1. 书城只有两个入口

新增 `BuiltinSources.STOREFRONT_IDS = {"qidian", "fanqie"}`，
`SourceManager.storefronts()` 只返回这两个；`BrowseScreen` 改用它。
采集站不再作为书城入口，只在「换源」时提供正文，但仍在书源管理里可单独启用。

### 2. 番茄按书自带的官方分类归类

这是本轮最关键的设计决定，因为实测发现**番茄压根没有「按分类列书」的接口**：

| 尝试 | 实测结果 |
|------|----------|
| HTML 首页 | 完全 JS 渲染，`__NEXT_DATA__` 内无书籍数据 |
| `/api/rank/list?type=N` | 仅 type=0/1/2 有数据，共 **26 本** |
| `page`/`gender`/`category_id`/`dim`/`app_id`/`limit`/`offset` | **全部无效**，返回结果完全相同 |
| `/api/category/list`、`/api/book/category`、`/api/rank/category` 等 8 条路径 | 全部 404 |
| 书籍页相关推荐 | 无，`/page/` 链接只有自己 |

但 `/api/book/info` 的 `category` 字段给了**官方三级分类**（`男生/都市/都市重生`）。
所以实现改为：抓全三档榜单 26 本 → 逐本补 `category` → **按官方分类归组**。

`FanqieSource` 相应重写：`allBooks()` 合并三档榜单 + 并发补分类 + 30 分钟缓存；
`list(category)` 按 `category` 前缀匹配（一级/二级都能命中）。

### 3. 采集站多镜像容错

新增 `BiqugeMultiSource`：一个书源持有一组镜像，换源时依次搜索，
正文抓不到时自动换站（用「书名 + 同章标题」对齐章节）。

## 二、实测数据（本轮最重要的产出）

### 采集站存活率：12 个候选只有 2 个能用

| 站点 | 对番茄 26 本的覆盖 | 状态 |
|------|-------------------|------|
| 望书网 | **8 / 26** | ✅ 主站 |
| 2K 小说 | 6 / 26 | ✅ 可作镜像 |
| 八一中文 | — | 搜索 ConnectionReset |
| 31xs / 91zww | 0 / 26 | 搜索页是「热门推荐」，非真结果 |
| 99mk/uuxs/biquw/ibiquges/wanbenxs/biqukun/txtduo | — | 搜索接口 404 |

另外发现：**望书网与八一中文返回完全相同的首页**（同为 28892 字节、同一套分类链接），
是同站群，所以「多站」的实际独立度比域名数量看起来低。

### 端到端覆盖率

番茄「男生/都市」15 本 → 7 本可从采集站读到完整正文：

```
✅ 最强龙婿 53章/2752字    ✅ 极品全才神婿 1034章/2599字
✅ 都市至尊战神 211章/2748字 ✅ 最强废婿 199章/4692字
✅ 至尊女婿 296章/1733字    ✅ 人生三十 1066章/1832字
✅ 最强弃子 3章/2287字      ✗ 其余 8 本无收录
```

**结论：7/15（47%）可读**。原因是采集站库存=已完结老书，榜单首页=新书。
这是数据源客观限制，已在面板文案与 README 中如实说明，不假装能做到 100%。

## 三、审查发现与处置

### P0（已修）

| # | 位置 | 问题 | 后果 | 修复 |
|---|------|------|------|------|
| 1 | `BiqugeMultiSource.parseList` | 只用 `listItem`（分类页卡片结构），搜索页是表格 `tr#nr` | 换源搜索**恒返回 0 本**，多镜像完全失效 | 加 `forSearch` 参数，优先用 `search*` 规则组 |
| 2 | `Book` 模型 | 缺 `category` 字段 | 无法承载番茄官方分类 | 新增 `category: String = ""` |

### P1（已修）

| # | 位置 | 问题 | 修复 |
|---|------|------|------|
| 3 | `FanqieSource.list` | 一度写成 `b.intro.startsWith(...) && false \|\| ...` 的死代码 | 重写为 `matchCategory(it, category.name)` |
| 4 | `BiqugeMultiSource` | 缺 `Category` import 导致编译失败 | 补 import |
| 5 | `BuiltinSourceRulesTest` | 旧断言「番茄分类指向 /api/rank/list」 | 更新为断言官方分类前缀 + 书城入口数量 |
| 6 | `SourceManager` | 多镜像分支一度没写进去（编辑未生效） | 重新应用并补 `MULTI_MIRROR` / `mirrorHosts` |
| 7 | `SwapDialog` | 「搜不到」文案没讲清原因 | 改为说明数据源限制 + 给出三条替代建议 |

### P2（记录未改）

| # | 问题 | 说明 |
|---|------|------|
| 8 | 番茄 26 本是硬上限 | 服务端限制，无解；已如实告知 |
| 9 | 起点每类仅 5 本、分页无效 | 站点限制 |
| 10 | 望书网/八一中文同站群 | 「多镜像」实际独立度低于域名数 |
| 11 | `BiqugeMultiSource.mirrorCount` 占位方法未被使用 | 可删，暂留作扩展点 |
| 12 | 番茄分类写死 10 个官方分类 | 若榜单换书，可能出现空分类；`全部` 可兜底 |

## 五、遗留与建议

- 番茄书籍池与起点每类 5 本是平台限制，无法通过代码扩大；
- 若要提高换源覆盖率，方向是**继续找存活采集站**（本轮已把候选从 10 扩到 12，收益递减）；
- 也可考虑接入社区维护的 Legado 书源（已有 `LegadoImporter`），由用户自行补充源。

## 六、结论

按需求完成三件事：书城只留起点/番茄、番茄按官方分类归类、采集站多镜像容错。
修掉 2 个 P0（其中「换源恒返回 0 本」会让整个换源功能失效）+ 5 个 P1。

如实说明：**换源覆盖率 47%（7/15）**，不是 100%，原因是采集站收录的是老书、
榜单是新书。这一点写进了面板文案、README 与版本说明，不做乐观包装。
