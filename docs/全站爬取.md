# 全站爬取：起点 / 番茄 → 本地库 → 阅读器

把起点中文网和番茄小说的**书目、目录、正文**抓到本机 SQLite，再通过一个本地
HTTP 接口喂给阅读器（书源「本地爬虫库」）。抓取的重活都在电脑上跑，手机只读 JSON。

```
起点 www.qidian.com ──┐
                      ├─ tools/spider（Python）──► data/library.db ──► tools/spider/serve.py
番茄 fanqienovel.com ─┘        限速/重试/断点续抓/字体反混淆              │
                                                                        ▼
                                                  http://<电脑IP>:8765/api/...
                                                                        │
                                                        阅读器「本地爬虫库」书源
```

代码位置：

| 文件 | 作用 |
|------|------|
| `tools/spider/qidian.py` | 起点：书库枚举、目录、正文 |
| `tools/spider/fanqie.py` | 番茄：榜单书池、目录、正文 |
| `tools/spider/fontfix.py` | 番茄正文的**字体反混淆**（轮廓哈希还原真字） |
| `tools/spider/net.py` | HTTP：cookiejar、重试、限速、编码识别 |
| `tools/spider/store.py` | SQLite：books / chapters / contents / filters / state |
| `tools/spider/serve.py` | 本地接口，给阅读器读 |
| `tools/spider/cli.py` | 命令行入口 |
| `tools/qidian_cookie.mjs` | 用 headless Edge 过起点的 `probe.js` 指纹页，取通行 cookie |

## 一、起点：怎么绕开「202 + probe.js」

实测（2026-10）：

| 请求 | 结果 |
|------|------|
| `www.qidian.com/all/` 裸 HTTP | **202**，209 字节，只有 `probe.js` 指纹脚本 |
| 同上，带浏览器跑出来的 cookie | **200**，10 万字节，完整书单 |
| `m.qidian.com/category/` | 200，但每类只有 5 本，翻页参数无效 |

所以流程是：**先用 headless Edge 跑一次页面，把 cookie 捞出来，之后全部走纯 HTTP**。

```bash
node tools/qidian_cookie.mjs          # 首次或 cookie 过期时跑；爬虫也会自动调它
# → tools/_probe/cookies.json，同时存进 data/cookies_qidian.json 复用
```

cookie 落盘后，起点侧的所有请求都是普通 GET，速度取决于限速设置（默认 0.35s/请求）。

### 书库枚举：`/all/` 是分页的，`data-pagemax` 给出上限

| 地址 | 说明 |
|------|------|
| `/all/`、`/all/page{N}/` | 全站书库，每页 20 本，`data-pagemax="50"` → **每个筛选 1000 本** |
| `/all/chanId{一级}/` | 按大类过滤（玄幻 21、奇幻 1、武侠 2、仙侠 22、都市 4…） |
| `/all/chanId{一级}-subCateId{二级}/` | 按二级分类过滤（修真文明、东方玄幻…） |

爬虫会先从总库页和各大类首页把**全部筛选地址**抓出来（实测 **137 个**），再逐个翻页。
所以「所有书籍」的口径是：`137 × 50 页 × 20 本 ≈ 13.7 万本`（站点列表能给出的上限）。

> 列表页的字数/更新时间用了自制字体（`qd_anti_spider/*.woff`）混淆数字，
> 爬虫不解析这两个字段（留 0），书名/作者/分类/简介/封面/状态都是明文。

### 目录：书籍页一次给全量

`https://www.qidian.com/book/{bid}/` 的 DOM：

```
div.catalog-volume                 # 卷
  h3.volume-name                   # 「长鲸月落 · 共234章 VIP」← 卷级 VIP 标记
  li.chapter-item a.chapter-name   # 章节，href = /chapter/{bid}/{cid}/
```

实测《玄鉴仙族》：9 卷 1707 章一次拿全，卷头带 `免费` / `VIP` 标记，
爬虫按卷继承 VIP 状态写入 `chapters.vip`。

### 正文：`main[id^=c-]`

```html
<main id="c-730944635" class="content ...">
  <p>　　陆江仙做了一个很长很长的梦……</p>
```

- 免费章：全文（实测单章 1400+ 汉字）。
- VIP 章：页面只给约 **130 字试读**，并带「订阅本章」标记 →
  爬虫存下这段试读，`contents.note='vip_preview'`，阅读器章节名后面标「（试读）」。

**不做**任何付费墙绕过：拿到的就是站点对未登录/未订阅访客公开的那部分。

## 二、番茄：书池小，但正文能还原

实测（2026-10）：

| 请求 | 结果 |
|------|------|
| `/api/rank/list?type=0/1/2` | 200，共 **26 本**（`page`/`gender`/`category_id` 参数全部无效） |
| `/api/category/list`、`/api/book/category`、`/api/book/recommend` | 404 |
| `/api/book/info?bookId=` | 200，官方三级分类（`男生/都市/都市重生`）、字数、状态 |
| `/api/reader/directory/detail?bookId=` | 200，**完整目录**（itemId + 标题 + needPay/isChapterLock） |
| `/reader/{itemId}` | 200，正文在 `__INITIAL_STATE__.reader.chapterData.content` |

番茄没有「按分类列书」的入口，所以书池上限就是榜单那 26 本——这是站点侧的限制，
不是爬虫漏抓。目录与正文则是完整的（实测《长生不可期》3497 章）。

### 字体反混淆（关键）

正文 HTML 里的字**几乎全是私有区码位**：

```html
<p><span></span>钟鸣响<span></span>，龙昊<span></span>座<span></span>殿<span></span>。</p>
```

页面用 `@font-face` 下发一份子集字体（`*.woff2`，约 47KB）来渲染这些码位。
实测这份子集：

- name 表写着 `This is a subset font of SourceHanSansSC-Normal`（思源黑体 Normal）；
- `cmap` 只有 362 个私有区码位，没有普通汉字；
- 字形名是 `gidNNNNN`（原字体字形号），**轮廓与思源黑体 2.002R 逐点一致**。

于是反混淆的做法是：拿**同一版**参考字体建一张「轮廓哈希 → 真字」表（44,259 条），
再用它把每章的私有区码位换回真字。实测 **362/362 字形精确命中**，还原后无残留。

> 版本要对得上：用 2.004R 只有 6/362 命中（Adobe 改过字形），2.002R 才是 362/362。
> 表只建一次，缓存在 `tools/spider/assets/glyph_table.json`；
> 同形字（康熙部首 `U+2F00` 与汉字同轮廓）按优先级取基本区汉字。

```bash
python -m tools.spider.cli fonts           # 首次自动下载参考字体并建表（约 1 分钟）
python -m tools.spider.cli fonts --force   # 重建
python -m tools.make_glyphmap              # 顺带刷新手机端内置字形表（assets）
```

## 三、存储与断点续抓

`data/library.db`（SQLite，WAL）：

```sql
books(key PK, source, native_id, title, author, cover, intro, category, status,
      words, updated, url, chapter_count, cataloged_at, fetched_at)
chapters(key, idx, title, url, native_id, vip, word, PK(key,idx))
contents(key, idx, text, chars, ok, note, ts, PK(key,idx))   -- note='vip_preview' 表示试读
filters(source, name, url, PK(source,name))
state(k, v)
```

- `key = 源:站点id`，例如 `qidian:1035420986`、`fanqie:6753575799414066190`；
- 重复跑不会重复入库（`ON CONFLICT DO UPDATE`）；
- 抓正文永远只挑「`chapters` 里存在、`contents` 里还没有 `ok=1`」的章节，
  所以随时 Ctrl-C、下次接着跑；
- 默认 0.35s/请求、3 次重试、单站点单线程（`SPIDER_DELAY` / `SPIDER_RETRIES` 可调）。

## 五、阅读器怎么接

代码：`app/src/main/java/com/modu/reader/source/LocalLibrarySource.kt`
（内置源 id `local_spider`，书城第三个入口「本地爬虫库」）。

1. 电脑上：`python -m tools.spider.cli serve --port 8765`
2. 手机与电脑同一 WiFi，查电脑 IP：`ipconfig`（如 `192.168.1.20`）
3. 阅读器 → 设置 → 书源管理 → 本地爬虫库 → 把 `baseUrl` 改成
   `http://192.168.1.20:8765`（默认为 `http://127.0.0.1:8765`，只对本机有效）
4. 书城选「本地爬虫库」→ 分类即抓到的分类体系（`仙侠/修真文明`、`男生/都市/都市重生`…）

接口（全部 GET，JSON）：

| 接口 | 说明 |
|------|------|
| `/api/health` | 探活 |
| `/api/stats` | 各源书数/章数/正文数 |
| `/api/categories` | 分类 + 每类书数 |
| `/api/books?cat=&page=&size=` | 分类书单 |
| `/api/search?key=&page=` | 按书名/作者搜 |
| `/api/book/{key}` | 详情 |
| `/api/book/{key}/chapters` | 目录（`vip` / `cached` 标记） |
| `/api/book/{key}/chapter/{idx}` | 正文（`preview=true` 表示试读片段） |

## 六、风控与节奏（实测踩过的坑）

两个站点都会**按 IP 限速**，不是「规则写错」：

| 现象 | 触发条件 | 爬虫的处理 |
|------|----------|------------|
| 起点整站 403（连 `probe.js` 都不给） | 连续几百个章节请求之后 | `--cooldown`（默认 120s）歇一轮再试；连续 3 次被挡就收工，下次重跑接着抓 |
| 番茄掉进「验证码中间页」 | 约 600 个正文请求之后 | 先 headless Edge 换 cookie；仍被挡就歇 `--cooldown`，连续 3 次收工 |
| 番茄某章 PC 页面只有 6KB 空壳 | 部分章节 | 自动换手机 UA 重取（实测 22KB 完整 SSR） |

节奏建议：

```bash
python -m tools.spider.cli --delay 1.0 qidian-content --limit 200 --cooldown 180
python -m tools.spider.cli --delay 2.0 fanqie-content --limit 200 --cooldown 300
```

- `--delay` 是**全局**参数，放在子命令前面（默认 0.35s ≈ 3 请求/秒）；
- 正文抓取**先抓免费章**（`ORDER BY vip`），把手上能拿全文的抓完再去拿试读；
- 一次别抓太多：起点一本 3000 章的书，光目录就 1 个请求，正文 3000 个请求 ≈ 半小时，
  中途被 403 就等几分钟，库里的数据不会丢（断点续抓）。

被风控期间想继续干活，可以先跑不需要正文的步骤（`qidian-catalog` / `fanqie-chapters` 都只读列表与目录）。

最省事的解法是**把你浏览器里的 cookie 导进来**（你在浏览器里过一次验证码，爬虫就不用再撞）：

```bash
# F12 → Network → 任意请求的 Request Headers → 复制 Cookie 那一段
python -m tools.spider.cli cookie --source fanqie --header "ttwid=...; msToken=...; __ac_signature=..."
# 或者浏览器扩展导出的 JSON 文件
python -m tools.spider.cli cookie --source qidian --file cookies.json
```

## 七、已知边界

| 项 | 情况 |
|----|------|
| 起点 VIP 正文 | 只有站点给的约 130 字试读；不订阅就拿不到，本项目不做绕过 |
| 起点列表的字数/更新时间 | 数字用自制字体混淆，未解析（留空/0） |
| 番茄书池 | 只有榜单 26 本，站点没有按分类列书的接口 |
| 番茄付费/锁章 | `needPay`/`isChapterLock` 为真的章节存不下正文，入库时标记 |
| 起点搜索 | PC 站搜索接口同样在指纹后面，未纳入（用列表枚举代替） |
| 抓取频率 | 默认 3 请求/秒，别把站点点着了；`SPIDER_DELAY` 可调大 |
| 版权 | 抓下来的内容只在本机自用；不要二次分发或商用 |

## 八、全量书目与签名（	ools/spider/sign/）

「全部书籍信息」在两个站点的可行路径完全不同：

| 站点 | 免签名能否拿全量书目 | 路径 |
|------|----------------------|------|
| 起点 | ✅ | /all/ 的 135–137 个筛选项 × 50 页 × 20 本 ≈ 13.5 万本上限，只需过一次 probe.js 拿 cookie |
| 番茄 | ⚠️ 只有榜单 26 本 | web 端没有列书/搜索接口，更多要走 App 的签名接口 |

全量枚举命令（断点续跑，完成的页会跳过）：

`ash
python -m tools.spider.catalog_full --source qidian          # 全量
python -m tools.spider.catalog_full --source qidian --filters 4 --pages 2   # 小样
python -m tools.spider.catalog_full --source fanqie          # 榜单 26 本
`

签名体系（番茄 X-Argus/X-Gorgon/X-Khronos，由 secsdk 的 libsign.so 生成）
本仓库只提供**骨架**：信封编解码、参数规范化、签名器契约与验收探针，
加密核心必须来自设备侧。详见 [	ools/spider/sign/README.md](../tools/spider/sign/README.md)。

`ash
python -m tools.spider.sign.selftest        # 信封/契约自测（全绿）
python -m tools.spider.sign.verify_cli --url https://api5-normal-sinfonlineb.fqnovel.com/reading/reader/full?item_id=... --param item_id=...
# 实测：无签名 -> 404；桩签名 -> 400（服务器不认假加密）
`

> 记住一句：**签名解决接口准入，不解决内容授权**。番茄付费章按账号权限下发，
> 起点 VIP 同样如此；签名过了也只是能调接口。

## 九、VIP 章全文补全（`tools/spider/vipfill.py`）

### 为什么不是「破解」

起点 VIP / 番茄付费章的正文，服务端**对未授权账号根本不下发**——页面里只有约 130 字试读，
`__INITIAL_STATE__` 里没有正文，签名、cookie 都改变不了这一点（见第八节实测）。
所以「拿到 VIP 全文」的正确做法不是绕过授权，而是**换源**：同一本书在采集站通常有全本。

### 做法：书名 + 章名对齐 + 正文校验

```bash
python -m tools.spider.vipfill --book qidian:1012237441 --limit 100   # 补一本
python -m tools.spider.vipfill --source qidian --books 3 --limit 200  # 补三本
python -m tools.spider.vipfill --source qidian --only-vip --limit 500 # 只补 VIP 章
```

三道关卡，缺一条就会写进错文：

| 关卡 | 规则 | 目的 |
|------|------|------|
| 书名 | 去掉「（校对版）」「全本」等噪声后**完全相等** | 防《全球高武之死气面板》这类同人作 |
| 目录 | 抽 20 章做章名归一化对齐，命中率 ≥ 30% | 防同名异书（《最强龙婿》在采集站是另一本 53 章的书） |
| 正文 | 抽 3 章比对 8 字指纹，连续窗口重合度 ≥ 35% | 防章号错位/占位页 |

正文指纹这里有个坑：**不能用等距抽样**。采集站和正站只要差一个标点，抽样点就整体错位，
重合度会从 97% 掉到 20%，于是把好书误判成「同名异书」——所以取开头 4000 字的连续窗口。
（`python -m tools.spider.selftest` 里有专门用例。）

补进来的正文 `note` 记成 `collector:<站点>`，接口原样透出，App 里能显示「来自采集站」。

### 实测（2026-10，望书网）

| 书 | 目录对齐 | 正文重合 | 补全结果 |
|----|---------|---------|---------|
| 全球高武 | 100% | 97% | 400 章批量补全中，单章 3800–5348 字 |
| 最强龙婿（番茄） | 0% | — | **被拒**：同名异书（采集站那本只有 53 章） |

单章补全后与站点试读对比：试读 126 字 → 补全 4310 字（完整章）。

### 边界

- 采集站没有的书补不了（新书/冷门书），会明确报「章名对不上」而不是写错文；
- 补进来的正文是采集站的排版（段落、标点可能和正站略有差异）；
- 作者感言/公告类章节跳过（`is_note_chapter`），这类章采集站常合并或改名，容易张冠李戴。
