# 付费墙：实测边界、手机端抓取、换源兜底

> 结论先说：起点 VIP 与番茄付费章的正文**内容不下发**，没有可以「解出来」的密文；
> 能在手机端做的是三件事——**账号态**、**免费内容**、**换源到采集站**。
> 本文把三条都落到代码里，并给出实测数字。

---

## 一、付费墙到底是什么

| 站点 | 机制 | 未付费时服务端给什么 | 能不能「技术绕过」 |
|------|------|----------------------|--------------------|
| 起点 VIP | 正文只对「已订阅/已购」账号下发 | 约 **130 字**试读 + 「订阅本章」按钮 | 不能：HTML 里根本没有后文（实测 `main[id^=c-]` 只有 5–7 段） |
| 番茄付费章 | `needPay` / `isChapterLock` 的章只给会员 | 空正文，或 `preview.chapterData` 的短片段 | 不能：`/reader/{id}` 的 `__INITIAL_STATE__` 里就没有正文 |
| 番茄 App 接口 | `X-Argus` / `X-Gorgon` 签名（native libsign） | 无签名 → **404 / 空响应**（实测） | 要逆向 native 签名，成本极高，且换版本就废 |

实测记录：

```
起点 VIP 章（免费账号）:
  main[id^=c-] 段落 7  字数 126  页面含「订阅本章」
番茄 App 接口（不带签名）:
  /reading/reader/full?item_id=...            → 404 Page not found
  /reading/bookapi/directory/all_items/v/...  → 200，空 body
```

所以「越狱式」绕过是不存在的；能落地的是下面三条。

---

## 二、路径 ①：免费内容（番茄为主）

番茄 26 本榜单书里，免费章占比很高（实测《西游天殇》1637 章里绝大多数可直接读全文）。
起点也有免费书，但 `/free/` 频道页在 HTTP 下时有时无（实测一次 41KB / 16 本，再一次 1.7KB 空壳），
不适合当稳定入口。

手机端已经能直接读：**「本机抓取」**（见第四节）会把免费章全文写进本地缓存。

---

## 三、路径 ②：账号态（你自己买的章节）

- 起点：登录后，**已订阅**的章节在 `/chapter/{bid}/{cid}/` 里就是全文（页面不再有「订阅本章」）。
- 番茄：登录 + 会员后，`chapterData.content` 才有正文。

App 侧实现：`WebGate.loginCookie(context, url)` 用一个 WebView 打开站点，
你手动登录完，它把登录态 cookie 取回来；之后 `DeviceCrawl` 的请求都会带上这份 cookie。
（没做自动登录——账号密码不落盘。）

> 这条路径等于「用官方客户端读」，只是把内容缓存到本地，能离线看。

---

## 四、路径 ③：换源到采集站（默认兜底）

这是真正能覆盖 VIP 章的办法：同一本书在采集站通常有全本。实测（望书网，2026-10）：

| 起点书 | 起点章数 | 采集站章数 | 抽样 12 章命中 | VIP 章正文实测 |
|--------|---------|-----------|---------------|----------------|
| 全职法师 | 3386 | 3418 | **11 / 12** | 1172 字 |
| 仙人消失之后 | 3204 | 3235 | **11 / 12** | 2071 字 |
| 修真聊天群 | 3189 | 3188 | **11 / 12** | 2017 字 |
| 凡人修仙传 | 2611 | 2565 | **11 / 12** | 3379 字 |

App 里的实现（`BookRepo` + `Paywall`）：

1. 抓正文，若命中 `Paywall.needsFallback`（空正文，或带「订阅本章」「试读结束」这类标记）或源直接报错；
2. 拿**书名**去采集站搜索，取前 2 个同名结果（`Paywall.sameBook` 允许「（校对版）」这类后缀）；
3. 归一化章名（去「第N章」「第N卷」前缀、去括注、去标点）后在采集站目录里定位；
4. **同名章按预期位置纠偏**：`hint = 起点章号 × 采集站章数 ÷ 起点章数`，
   取离 hint 最近的那个（采集站常见重复的「感谢」「请假条」，只取第一个会错位到书尾）；
5. 命中且正文 > 220 字就返回并写入本地缓存。

两条与缓存有关的纪律（v1.8.1 起）：

- **试读片段不进正文缓存**：否则下次直接命中缓存，再也不会去兜底；
- 兜底**只缓存命中**：没命中不写缓存，下次重跑还能再试（一次临时网络失败不该让这章永久失效）。

`Paywall` 的这批纯函数有单测（`PaywallAndGlyphTest`）：付费判定、`needsFallback` 与短章的区别、
章名归一化（含「第11卷 第3章」多层前缀）、同名章纠偏、书名匹配。

## 五、手机端：本机抓取（不依赖 PC）

`source/DeviceCrawl.kt` + `net/WebGate.kt`：

```
点「本机抓取」
   │
   ├─ WebGate：隐藏 WebView 打开 qidian.com/all/ 或 fanqienovel.com
   │     └─ 让 probe.js / 验证码 sdk 跑完 → CookieManager 取 cookie
   ├─ 抓目录（起点 div.catalog-volume；番茄 __INITIAL_STATE__.page.chapterListWithVolume）
   ├─ 逐章抓正文（起点 main[id^=c-]；番茄 reader.chapterData.content）
   │     └─ 番茄：FanqieGlyph.decode() 用内置字形表把私有区码位换回真字
   ├─ 免费章 → 写本地缓存（离线可读）
   └─ VIP/付费章 → 留给「换源兜底」按章捞
```

番茄字形表是**内置**的：`assets/fanqie_glyphs.json`（362 条，9KB），
由 PC 端轮廓哈希工具生成——因为实测「一份混淆字体 = 一套替换表，全站通用」，
手机端不需要解析 woff2。

### 手机端 vs PC 端

| 能力 | PC（tools/spider） | 手机（DeviceCrawl） |
|------|--------------------|---------------------|
| 过起点 probe.js | headless Edge + CDP | **WebView 跑一遍** |
| 过番茄验证码页 | headless Edge | 同上 |
| 番茄字体还原 | 解析 woff2 + 轮廓哈希 | 内置字形表 |
| 全站枚举 13 万册 | ✅ 适合（限速/断点续抓） | ❌ 耗电、易风控 |
| VIP 章 | 拿不到 | 拿不到 |
| 抓完能离线读 | 需 PC 在局域网 | ✅ 直接进 App 缓存 |

所以：**手机抓你在看的那几本，PC 铺全站**，两边共用同一套 SQLite 结构（PC 侧经「本地爬虫库」读）。

## 六、已知限制（别踩第二次）

| 现象 | 原因 | 处理 |
|------|------|------|
| 起点整站 403 | 按 IP 限速，抓几百章后触发 | 歇几分钟；PC 侧 `--cooldown`，手机侧重试即可 |
| 番茄掉「验证码中间页」 | 同上 | WebGate 重过一次 cookie；仍不行就歇 |
| 番茄正文还是方块/乱码 | 字形表没覆盖（站点换了字体） | 重新生成：`python -m tools.make_glyphmap`，替换 asset |
| 换源命中但正文不对 | 采集站章名重复，位置错 | 已按「预期位置」纠偏；仍错就在换源面板手动选别的站 |
| 笔尖中文 SSL 报错 | 该站证书过期 | 用望书网（默认启用）兜底 |
