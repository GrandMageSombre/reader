# 破解全量资源：起点 / 番茄一条龙

> 这篇讲的是 `tools/spider/crack/` 这一层：**同一份资源同时试多条入口，谁给全文用谁**。
> 单点抓取在 `qidian.py` / `fanqie.py`，本篇只讲「组合拳」和实测数字。
>
> 命令入口：`python -m tools.spider.harvest`（`--plan` 先看口径）。
> 实测数据均标了日期与版本：**2026-11-06 / v1.15.0**；界面与文档口径见第九节。

---

## 一、什么叫「全部资源」

四个层次，缺一层就不算全：

| 层 | 起点 | 番茄 |
|----|------|------|
| 书目 | 137 个筛选 × 50 页 × 20 本 ≈ **13.7 万本**上限，另加限免/完本/4 个榜单 | 榜单 **26 本**（web 侧硬上限）；扩池只能走 App 签名接口 |
| 目录 | 书籍页一次给全量（分卷 + 免费/VIP 标记） | `/api/reader/directory/detail`（含 `needPay`/`isChapterLock`） |
| 正文 | 免费章：PC 页 / 移动页 / ajax 三入口 | `reader` SSR + 轮廓哈希还原私有区码位 |
| 付费章 | 试读 → 移动/ajax → **采集站按章对齐补全** | App 签名接口 → 批量接口 → **采集站兜底** |

一句话：**站内拿不到的，站外按「书名 + 章名 + 预期位置」补齐**；这是唯一稳定可复现的路径。

## 二、破解层的结构

```
tools/spider/
├── harvest.py              # 一条龙 CLI（本篇的主角）
├── crack/
│   ├── plan.py             # 判定/策略/入口表（纯函数，55 条自测）
│   ├── qidian.py           # 起点四路：web / mobile / ajax / collector
│   ├── fanqie.py           # 番茄四路：web / app / batch / collector
│   ├── appclient.py        # 番茄 App 签名头装配 + 业务码判定
│   ├── collectors.py       # 采集站多镜像：按书名找书、按章对齐取正文
│   ├── runner.py           # 编排：并发、断点续抓、风控熔断、统计
│   └── selftest.py         # python -m tools.spider.crack.selftest（全离线）
├── sign/                   # 签名信封 / 契约 / 验收探针（App 接口要用）
└── qidian.py, fanqie.py    # 单点抓取（被 crack 层调用）
```

分工的原则只有一条：**判定与编排分离**。
「这段正文算不算全文」只写在 `plan.classify` 里，「先试谁后试谁」只写在 `plan.STRATEGIES` 里，
业务代码只认 `Cracked.usable`。这样换站点、加路数都只动一处。

> 诚实版：加一条**新路**只改 `plan.STRATEGIES` + 对应 crack 类的 `_route` 一个分支；
> 加一个**新站点**要动 4 处——`plan.TARGETS`、一个新的 `crack/<site>.py`、
> `runner._crack_for` 一处分支、`harvest.py` 的 `--source` 选项。别的地方不用改。

### 判定表（与 App 侧 `Crack.Kind` / `Paywall` 完全一致）

| 成色 | 判据 | 处理 |
|------|------|------|
| `ok` | 剥掉噪声行后 ≥ **220 字**，且没有试读标记 | 入库，`contents.ok=1` |
| `short` | 有字但 < 220（公告、感言、被截断） | `ok=0`，下一轮再试 |
| `vip_preview` | 正文/备注里出现「订阅本章」「试读结束」等 | 换下一条路 |
| `locked` | 备注里出现 `chapterLock` / `needsPay` 等 | 换下一条路 |
| `empty` | 空正文 | 换下一条路 |
| `blocked` | 403 / 验证码中间页 / 网络异常 | **不记失败**，触发熔断歇一会儿 |

> 阈值 220 是有来历的：起点 VIP 试读实测 **126–136 字**，正常章 1000+；
> 而作者感言常只有一两百字，所以「短」只用来统计、不用来触发换源
> （这条纪律在 App 侧 `Paywall.needsFallback` 里已经写过一次，PC 端照抄）。

## 三、四路策略

### 起点

| 路 | 地址 | 实测（2026-11-06，免费账号 cookie） |
|----|------|--------------------------------------|
| `web` | `/chapter/{bid}/{cid}/` | 免费章全文；VIP 章 **136 字 + 「订阅本章」** |
| `mobile` | `m.qidian.com/chapter/{bid}/{cid}/` | HTTP 200 但只有 **825 字节 WAF 脚本壳**，无正文节点 → 判 `blocked` |
| `ajax` | `ajax/chapter/chapterInfo` | `{"code":1}`（未登录/无权限）→ 判 `empty` 并留业务码 |
| `collector` | 采集站镜像 | VIP 章的实际来源；三道闸后才用（书名全等 / 目录对齐 ≥30% / 正文 8 字指纹 ≥35%） |

结论：**起点 VIP 章的破解点是 `collector`，不是签名**。`mobile` / `ajax` 保留是因为
① 有账号 cookie 时它们会给更多（WebGate 登录态）；② 站点改版后可能换路，代码不用改结构。

### 番茄

| 路 | 地址 | 实测 |
|----|------|------|
| `web` | `/reader/{itemId}` | 免费章 SSR 全文（首章实测 **2180 字**，字形 100% 还原）；付费章 **75 字** |
| `app` | `/reading/reader/full` | 需 `X-Argus`/`X-Gorgon`/`X-Khronos`；无签名器 → HTTP 400 |
| `batch` | `/reading/reader/batch_full/v` | 一次多章，风控更松，整本补时优先 |
| `collector` | 采集站镜像 | 付费章兜底（**实测覆盖率只有 1/26**，见第四节） |

## 四、实测数据（2026-11-06）

### 起点入口有效性

| 入口 | 状态 | 首屏书数 |
|------|------|----------|
| `/all/` 全站书库 | 200 | 20（99 KB） |
| `/free/` 限时免费 | 200 | 16（41 KB） |
| `/all/action1/` 完本 | 200 | 20（101 KB） |
| `/rank/yuepiao/` 月票榜 | 200 | 20（74 KB） |
| `/rank/readindex/` 阅读指数 | 200 | 20（61 KB） |
| `/rank/collect/` 收藏榜 | 200 | 20（72 KB） |
| `/rank/newbook/` 新书榜 | **404** | 0（已从入口表剔除） |

### 起点 VIP 章四路（《夜无疆》，869 章 / 771 章 VIP）

```
web      short        136 字   vip_preview
mobile   empty          0 字   移动页正文容器未命中（WAF 壳 825B）
ajax     empty          0 字   ajax code=1
```

### 番茄

| 项 | 数值 |
|----|------|
| 榜单书池 | **26 本**（type=0/1/2 各 7/10/9 本，去重后 26） |
| 加 `dim=1..10` 扩池 | **仍是 26 本**（维度参数被忽略，扩池增益 0；默认已不再发这些请求） |
| 目录（《最强龙婿》） | **336 章**（—《极品全才神婿》1034 章） |
| 首章正文 | **2180 字**，字形还原无残留私有区码位 |
| 付费章（第 10 章） | **75 字** → `short`，必须走采集站/App 接口 |
| App 接口无签名 | `full` → HTTP 400；`search` 修掉参数编码（中文关键字）后仍非 0 业务码 |

### 采集站覆盖率（付费章破解的真实上限）

拿番茄榜单 26 本逐本去采集站找（书名全等 → 目录对齐 ≥30% → 正文指纹 ≥35%），实测：

```
✅《极品全才神婿》本地 1034 章 · 采集站 wangshu 1034 章 · 对齐 100%
✗ 《最强龙婿》本地 336 章 · 同名异书被拦（采集站那本是 53 章的另一本）
✗ 《都市至尊战神》969 章 / 对齐 0%      ✗ 《人生三十》1009 章 / 对齐 5%
✗ 其余 22 本 · 未收录或对齐 0–10%
─────────────── 覆盖 1 / 26 本
```

**为什么这么低**：番茄榜单是新书，采集站库存是**已完结、较热的老书**；
另外同名异书很多（《最强龙婿》就有两本同名），三道闸宁可放过也不串内容。
反过来，目标若是已完本热门书，命中率很高（v1.13 实测《凡人修仙传》1027 章全本可补）。

> 番茄「全部书籍」这件事必须在文档里说死：web 侧就是 26 本，**签名解决的是接口准入，
> 不是内容授权**。App 接口即使签名通过，也是「按榜单/搜索/分类逐页拿」，
> 没有「一次列全站」的接口——这是产品结构，不是技术限制。

## 五、用法

```bash
# 0) 先看口径（不联网）
python -m tools.spider.harvest --plan

# 1) 起点：书目（6 个入口 × 分页）→ 目录 → 正文
python -m tools.spider.harvest --source qidian --what all \
    --pages 3 --limit-books 120 --limit-chapters 400 --workers 2

# 2) 番茄：扩池 + 目录 + 正文
python -m tools.spider.harvest --source fanqie --what all --limit-chapters 300

# 3) 只补 VIP / 付费章（免费章已经抓完了）
python -m tools.spider.harvest --source qidian --what content --only-paid

# 4) 两个站一起，跑完直接喂阅读器
python -m tools.spider.harvest --source both --what all --workers 3 --json data/crack.json
python -m tools.spider.cli serve --port 8765
```

| 参数 | 作用 | 建议 |
|------|------|------|
| `--what` | books=书目 / catalog=目录 / content=正文 / all=全流程 | 断点续跑，分步跑也行 |
| `--workers` | 正文并发数 | 站点限速是**全局**的（`net._throttle`），调大不涨吞吐、只增被封风险；1–3 |
| `--delay` | 请求间隔（秒） | 默认 0.35；被 403 后调到 1.0–1.5 |
| `--limit-chapters` | 本轮抓几章 | 0 = 不限（会跑很久） |
| `--only-paid` / `--only-free` | 只抓付费章 / 只抓免费章 | 分开跑便于估时间 |
| `--signer` | 番茄签名器命令 | 见第六节 |
| `--json` | 统计落盘 | 便于对比两轮的战果 |

> `--skip-vip` 这类 flag 是 `store_true`，**不能**写 `--skip-vip false`（argparse 会报错）；
> 想要「只抓付费章」用 `--only-paid`。

### 断点续抓怎么算的

| 层 | 判据 | 重跑行为 |
|----|------|----------|
| 书目 | `books.key` 已存在 | 跳过 |
| 目录 | `books.cataloged_at != 0` | 跳过整本 |
| 正文 | `contents.ok = 1` | 跳过；`ok=0`（试读/空/失败）会再试 |

**试读片段绝不写 `ok=1`** —— 否则下一轮直接命中缓存，再也不会去补。
这条在 `runner.harvest_content` 里是硬编码的，不靠调用方自觉。

## 六、接番茄签名器

签名值只能由 `libsign.so` 算（native，随版本变），所以本仓库**不实现加密**，只定契约：

```bash
# 1) 从已装 App 的设备抽 so
adb shell "run-as com.dragon.read ls lib/arm64-v8a"    # 或直接解压 APK 的 lib/
adb pull /data/app/.../lib/arm64-v8a/libsign.so .

# 2) 写包装：stdin 收 JSON，stdout 出签名头
cat > signer.py <<'EOF'
import ctypes, json, sys
lib = ctypes.CDLL("./libsign.so")
req = json.load(sys.stdin)          # {device_id, aid, url, params, body, ts_ms}
# 入口名随版本变（Java_* / sign / doCommand），按 so 的导出表挑
out = {"X-Argus": "...", "X-Gorgon": "8400...", "X-Khronos": str(req["ts_ms"] // 1000)}
print(json.dumps(out))
EOF

# 3) 接上
FANQIE_SIGNER="python signer.py" python -m tools.spider.harvest --source fanqie --what books

# 4) 先验「服务器认不认」，别拿 HTTP 200 当成功
python -m tools.spider.sign.verify --url "https://api5-normal-sinfonlineb.fqnovel.com/reading/reader/full?item_id=..." \
  --signer "python signer.py"
```

验收标准只有一条：**业务码 `code == 0`**。字节系失败也是 HTTP 200。

## 七、和 App 的关系

| 能力 | PC（`harvest`） | App（详情页按钮） |
|------|-----------------|--------------------|
| 全站书目 | ✅ 13.7 万本上限 | ❌ 只按分类翻页 |
| 整本目录+免费章 | ✅ | ✅「下载整本」（`DeviceCrawl`） |
| 起点移动站二路 | ✅ | ✅（`DeviceApi.qidianTextMobile`） |
| VIP/付费章补全 | ✅ `collector` 链 | ✅ 新增「**破解补全（VIP / 付费章）**」（`BookRepo.crackFill`） |
| 判定口径 | `crack/plan.classify` | `Crack.of`（同一阈值、同一标记表） |
| 落库 | `data/library.db` | App 内 SQLite |

App 侧「破解补全」做的事：把目录里**没有正文**的章逐章跑一遍 `content()`，
站方给试读就自动去采集站对齐补；只把 `Crack.isFull` 的章写缓存；
连续 3 次风控就停（不再越抓越封）。

## 八、失败排查

| 现象 | 原因 | 处理 |
|------|------|------|
| 起点 `HTTP 202`，正文空 | 没过 `probe.js` 指纹页 | 脚本会自动用 headless Edge 过一次；失败就调大 `--delay` |
| 起点成批 403 | 按 IP 限速 | 歇 2–5 分钟；`--workers 1 --delay 1.2` |
| 起点 VIP 章始终 `short` | 采集站没有这本（新书） | 换时间再跑；或 `--signer` 走 App 接口；或换源到采集站读 |
| 番茄掉验证码中间页 | 请求量到阈值 | 脚本自动过一次挑战页；仍不行就停 10 分钟 |
| 番茄正文是方块 | 字形表没覆盖（站点换了字体） | `python -m tools.make_glyphmap` 重建，替换 `assets/fanqie_glyphs.json` |
| 番茄 App 接口 `code != 0` | 没签名器 / 签名过期 | 见第六节；`verify.py` 先验 |
| 采集站 503 | 限流 | 脚本会自动跳到下一个镜像；全挂就等一会儿 |
| 补进来的正文串书 | 同名异书 | 三道校验（书名全等 + 对齐率 ≥30% + 正文 8 字指纹 ≥35%）；仍错就在换源面板手动选站 |

## 九、边界（别自欺）

- **站方不下发的正文，站内解不出来**：起点 VIP 页 HTML 里就没有后文，番茄付费章的
  `__INITIAL_STATE__` 里也没有。破解层的价值在「换路 + 站外对齐」，不在「解密」。
- **采集站覆盖率不是 100%**：库存是已完结老书，新书还没被搬运。实测番茄「男生/都市」15 本里
  7 本可补全，这是数据源上限。
- **签名器换版本就废**：`libsign.so` 随 App 更新变化，`X-Argus` 的段结构也可能变；
  契约层（`sign/secsdk.py`）保证「换签名器只改一行命令」，但签名器本身要自己维护。
- **限速是硬约束**：并发开了不是更快，只是更早被封。
- 本项目把这些都当**本地测试夹具**处理，产出的数据只用于自用阅读工具。
