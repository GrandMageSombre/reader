# 手机直抓：App 内的起点 / 番茄书源

不想连电脑、不想跑 `serve.py`、不想填 IP —— 用这个内置书源就够了。

```
书城 →「手机直抓」→ 选分类 → 点书 → 读
        │
        ├─ WebGate：隐藏 WebView 打开站点，让 probe.js / 验证码 sdk 跑完 → 取 cookie
        ├─ DeviceHttp：普通 GET（自动带票；遇到挑战页自动换票重试一次）
        ├─ DeviceApi：起点书库 / 目录 / 正文、番茄榜单 / 目录 / 正文
        └─ DeviceParsers：CSS/JSON 解析（纯函数，单测覆盖）
```

## 一、能做什么

| 能力 | 说明 |
|------|------|
| 起点书库 | `/all/chanId{id}/`、`/all/chanId{id}-page{n}/`，每页 20 本；书城给了 15 个大类 |
| 起点目录 | 书籍页一次给全量（实测 1707 章 / 9 卷），免费/VIP 卷标记会反映到章节 |
| 起点正文 | `main[id^=c-]`；VIP 章只有约 130 字试读（换源可读全文） |
| 番茄榜单 | `/api/rank/list?type=0/1/2`，共 26 本（站点没有按分类列书的接口） |
| 番茄目录 | `/api/reader/directory/detail`，全量 |
| 番茄正文 | `/reader/{itemId}` 的 `__INITIAL_STATE__` → **内置字形表还原私有区码位**（362 条） |
| 起点搜索 | 尽力而为：`/soushu/{关键词}.html` 能拿到就返回；拿不到回空（界面提示去分类里翻） |

## 二、为什么不需要配置

起点 PC 站会先给 202 + `probe.js` 指纹页，番茄抓多了会给「验证码中间页」。
两者本质都是**要一个真浏览器跑一遍 JS**：

- PC 端用 headless Edge（`tools/qidian_cookie.mjs`）；
- 手机端用 **App 内的隐藏 WebView**（`net/WebGate.kt`）—— 手机上本来就有 Chromium，天然过得去。

拿到 cookie 后存在 `DeviceHttp` 里（按 host 缓存，10 分钟 TTL），后续都是普通 GET。
挑战页再出现时（页面 < 3KB 或含 `TCaptcha`），自动换票重试一次。

## 三、与其它两条抓取路径的关系

| 路径 | 入口 | 需要 PC | 适合 |
|------|------|---------|------|
| **手机直抓**（本页） | 书城「手机直抓」 | ❌ | 手机上随手看几本 |
| 本地爬虫库 | 书城「本地爬虫库」 | ✅ 要跑 `serve.py`（**IP 自动发现**，不用填） | 想铺全站、想批量导 TXT |
| 内置发现源（起点/番茄） | 书城「起点中文」「番茄小说」 | ❌ | 按官方分类发现书，正文靠换源 |

三者共用同一套解析与付费判定（`DeviceParsers` / `Paywall`），所以行为一致。

## 四、常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 第一次进分类转圈 5–10 秒 | WebView 正在过反爬 | 正常，之后同 host 复用 cookie |
| 列表空、提示「被风控」 | 请求太密被限速 | 等几分钟再点刷新；不要连续猛刷 |
| 起点书点进去目录为空 | 同 IP 限速 | 同上 |
| 番茄正文是方块/乱码 | 站点换了混淆字体 | 重新生成字形表：`python -m tools.make_glyphmap`，替换 `app/src/main/assets/fanqie_glyphs.json` |
| VIP 章只有一小段 | 服务端只下发试读 | 用「换源阅读」读采集站全文（自动兜底） |
| 搜索没结果 | 起点搜索页是 JS 跳转，HTTP 拿不到 | 用分类翻，或换关键词；也可用其它书源搜 |
