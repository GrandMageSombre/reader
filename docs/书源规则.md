# 书源规则说明

一份书源 = 一份 JSON。引擎只做三件事：**拼 URL → 抓 HTML → 按 CSS 规则取值**。
所有 `{page}` / `{key}` 占位符在发请求前替换。

## 一、顶层字段

| 字段 | 必填 | 说明 |
|------|------|------|
| `id` | 是 | 唯一标识，只能英文数字下划线；不能是 `demo`（内置源占用） |
| `name` | 是 | 显示名，书城顶部的书源标签 |
| `baseUrl` | 是 | 站点根地址，如 `https://example.com`；相对链接都以它为基准解析 |
| `charset` | 否 | 强制编码，`utf-8` / `gbk` / `gb18030`；不填则自动从响应头或 `<meta>` 里嗅探 |
| `headers` | 否 | 附加请求头（UA、Referer、Cookie 都可以放这里） |
| `categories` | 否 | 分类数组，见下 |
| `enabled` | 否 | 是否启用，默认 true |
| `note` | 否 | 备注，会显示在书源管理里 |

### categories

```json
"categories": [
  { "name": "玄幻", "url": "/list/xuanhuan/{page}.html" }
]
```

`{page}` 会被替换成 1、2、3…；不带 `{page}` 也可以（只抓第一页）。
**分类完全对应站点自己的分类**，引擎不做任何归类。

## 二、规则语法

所有规则都是一行字符串：`CSS选择器@取值`。

| 取值 | 含义 |
|------|------|
| `text`（默认） | 节点可见文本，去首尾空格 |
| `ownText` | 只取本节点直属文本（不含子节点里的字） |
| `html` | 节点内部 HTML |
| `href` / `src` / `title` / `alt` / `value` / `content` | 对应属性（`content` 常用于 `<meta>`） |
| `data-xxx` | 任意 `data-*` 属性，如 `img@data-src` |
| `attr:xxx` | 任意属性，如 `attr:data-original` |
| `abs:href` / `abs:src` | 转成绝对地址（相对 `baseUrl` 解析） |

三条书写规则：

1. 省略 `@` → 等同于 `选择器@text`，例如 `"chapterList": "#list dd a"` 可以写；
2. **只写取值**（`text` / `href` / `src`…）→ 表示对「当前节点自己」取值。
   章节列表必须用这种写法：`"chapterName": "text"`、`"chapterLink": "href"`；
3. 匹配不到返回空串，不会抛异常；但 `content` 匹配不到会明确报错「正文规则没匹配到内容」。

> **两个容易踩的坑**：
> - 属性选择器里带引号没问题（`meta[property='og:image']@content`），引擎只在**引号之外**找 `@`；
> - `chapterName` / `chapterLink` 是**相对章节节点自己**求值的。写 `h2` 表示「章节节点的子元素 h2」，
>   所以要取节点自身的文本仍然写 `text`，别写成 `a`（那会去找子元素 a）。

## 三、rules 字段表

### 列表页（分类 / 搜索共用）

| 字段 | 说明 |
|------|------|
| `listItem` | **必填**。每本书的容器选择器，返回一组节点 |
| `listName` | 书名，默认 `a@text` |
| `listLink` | 详情页链接，默认 `a@href`；相对地址自动转绝对地址 |
| `listAuthor` | 作者 |
| `listCover` | 封面，通常 `img@src` 或 `img@abs:src` |
| `listIntro` | 一句话简介 |
| `searchUrl` | 搜索地址模板，支持 `{key}`（自动 URL 编码）和 `{page}` |

### 详情页

| 字段 | 说明 |
|------|------|
| `detailName` | 书名，取不到就用列表页带过来的 |
| `detailAuthor` | 作者 |
| `detailCover` | 封面 |
| `detailIntro` | 简介 |
| `detailStatus` | 状态（连载 / 完结） |

> 详情页和目录页通常是同一个地址，引擎只在 `detail()` 与 `chapters()` 各抓一次，不重复请求。

### 目录

| 字段 | 说明 |
|------|------|
| `chapterList` | **必填**。章节节点集合，如 `#list dd a` |
| `chapterUrl` | 目录页地址。留空 = 目录和详情页同一地址；写 `地址` / `{page}` 模板 = 直接当目录页；写 `选择器@href`（如 `a#details-menu@href`）= 从详情页里取出目录页地址 |
| `chapterName` | 章节名，默认 `text`（对节点自己取值） |
| `chapterLink` | 章节链接，默认 `href` |
| `chapterNext` | 「下一页」链接规则（写 `选择器@href`），跟着它逐页翻目录；与 `chapterUrl` 的 `{page}` 二选一 |
| `chapterReverse` | 站点是倒序排列时设 `true`，引擎反转成自然顺序 |

**只拿到一部分章节时**，多半是下面三种情况：

```json
// 情况一：目录和详情页不是同一个地址（详情页 /book/1.html，目录在 /book/1/）
"chapterUrl": "/book/1/"

// 情况一（更通用）：从详情页里取目录链接
"chapterUrl": "a#details-menu@href"

// 情况二：目录本身分页（一个页面只列一部分章节）
"chapterUrl": "/book/1/{page}.html"        // 模板法：page 从 1 开始，抓到空页为止
"chapterNext": "div.pager a.next@href"     // 或者翻页链接法，二选一
```

> 分页顺序按「第 1 页 → 第 2 页 → …」拼接，`chapterReverse` 作用于**拼接后的全量**目录。
> 抓到空页、同一页重复出现、同一章重复出现、或者下一页取不到（404）都会自动停下（已抓到的目录保留）；
> 目录最多翻 20 页，防止规则写错时无限翻。

### 正文

| 字段 | 说明 |
|------|------|
| `content` | **必填**。正文容器，取它的全部文本；匹配到**多个**容器时按文档顺序合并（嵌套命中的内层会被去掉） |
| `contentNext` | 「下一页」链接规则（写 `选择器@href`），站点把一章拆成 `/1.html`、`/2.html` 时用它拼完整 |
| `contentClean` | 清理规则数组：普通选择器会被 `remove()`；以 `re:` 开头的是正则，**命中该正则的整行会被丢掉** |

### 搜索结果页与分类页结构不同时

很多站点的**分类页是卡片、搜索结果是表格**，同一个 `listItem` 覆盖不了两者。
这时用 `search*` 这组字段单独配搜索结果页：

```json
{
  "listItem": "div.item",              // 分类页：卡片
  "listName": "dl dt a",
  "listLink": "dl dt a@href",

  "searchUrl": "/modules/article/search.php?searchkey={key}",
  "searchItem": "table.grid tr#nr",    // 搜索页：表格行
  "searchName": "td:nth-of-type(1) a",
  "searchLink": "td:nth-of-type(1) a@href",
  "searchAuthor": "td:nth-of-type(3)"
}
```

`searchItem` 留空 → 搜索结果页复用 `listItem` 那组规则（绝大多数站点是这样）。

> 这条能力是「换源」的前提：换源靠的就是在第三方源里**按书名搜索**。

正文也能「一次配全」：

```json
"content": "#content",                    // 只匹配一个容器就行
"contentNext": "a:contains(下一页)@href",  // 有下一页就接着抓，最多拼 10 页
```

> 多容器站点（`#content` + `#content2` 这种）不需要额外配置：`content` 的选择器写成能同时命中它们的写法即可，
> 例如 `"#content, #content2"`，或者直接 `"div.showtxt"`。
> 后续页抓取失败时保留已抓到的部分并结束（首页失败才会报错），避免整章变成错误页。

正文按块级标签（`p` / `div` / `br` / `h1-6` / `li` / `tr`…）拆段，一行一段，空行丢弃。

`contentClean` 示例：

```json
"contentClean": ["script", "style", ".ad", "#recommend", "re:本章未完", "re:^\\s*第\\d+页"]
```

## 四、一份能跑的最小书源

```json
{
  "id": "demo_min",
  "name": "最小示例",
  "baseUrl": "https://example.com",
  "categories": [
    { "name": "全部", "url": "/books?page={page}" }
  ],
  "rules": {
    "listItem": ".book-item",
    "listName": ".title@text",
    "listLink": ".title@href",
    "listAuthor": ".author@text",
    "listCover": "img@abs:src",
    "detailName": "h1@text",
    "detailIntro": "#intro@text",
    "chapterList": "#catalog li a",
    "chapterName": "text",
    "chapterLink": "href",
    "content": "#content",
    "contentClean": ["script"]
  }
}
```

## 五、调试顺序（建议）

规则写错时，按这个顺序定位，一次只验一层：

1. **分类**：书城 → 选书源，分类列表能出来，说明 `categories` 拼的 URL 是对的；
2. **列表**：点一个分类，书能出来，说明 `listItem` / `listName` / `listLink` 对；
3. **详情**：点书能进详情页，说明 `detail*` 对（这几个字段错了不会崩，只是显示空）；
4. **目录**：详情页的章节数不为 0，说明 `chapterList` / `chapterName` / `chapterLink` 对；
5. **正文**：进阅读器能看到字，说明 `content` 对；出现广告或页脚，加 `contentClean`。

常见问题：

| 现象 | 多半是 |
|------|--------|
| 分类点进去空白 | `listItem` 写错（可以先在浏览器 F12 里 `document.querySelectorAll()` 试一下） |
| 书名是空的 / 一串乱码 | `listName` 选到了容器而不是文字，试试 `h3 a@text` 这种具体写法 |
| 章节名全是「最新章节」之类的噪声 | `chapterList` 选到了推荐区，换更精确的选择器 |
| **目录只列出一部分章节** | 目录不在详情页 → 填 `chapterUrl`；目录本身分页 → `chapterUrl` 加 `{page}` 或配 `chapterNext` |
| 正文只有一行 | `content` 选到了外层容器但站点用 `div` 分行，检查是否被 `contentClean` 误删 |
| **正文只有半章** | 站点把一章拆成 `/1.html`、`/2.html` → 配 `contentNext`；正文分散在多个容器 → `content` 写成 `"#content, #content2"` |
| 中文乱码 | 在书源里加 `"charset": "gbk"` |

## 六、第三方书源（Legado / 「阅读」格式）

社区里的书源大多是 Legado（「阅读」APP）格式，字段名和语法与本项目不同。
在「书源管理 → 导入」里直接粘贴即可，应用会自动识别并转换。

**能等价的写法会被翻译**：

| Legado | 转换成 | 说明 |
|--------|--------|------|
| `class.item` | `[class*=item]` | class 名通常带构建哈希，用包含匹配更稳 |
| `id.list@tag.a` | `#list a` | `@tag.x` 是「往下找子元素」 |
| `tag.a@href` | `a@href` | |
| `tag.p@text` | `p` | `text` 是本引擎默认取值，可省略 |
| 尾部 `##正则` | 丢弃 | 本引擎的清理走 `contentClean` |
| `{{key}}` / `{{page}}` | `{key}` / `{page}` | 仅限纯 GET 地址 |

**不会转换**（字段留空 + 备注写明原因）：

| 写法 | 原因 |
|------|------|
| `@js:` / `<js>` | 需要 JS 运行时，本引擎只做静态解析 |
| `//...` XPath | 只支持 CSS 选择器 |
| `POST` / 带 body 的 searchUrl | 抓取层只发 GET |
| `tag.p.1` / `class.x.0` 这类索引 | Legado 的 `.1` 是「同级匹配里的第几个」，与 CSS `:nth-of-type` 语义不同，硬译会取错节点 |

示例来源：

- 源仓库：<https://www.yckceo.com/yuedu/shuyuan>
- Yiove 综合书源库：<https://shuyuan.yiove.com/complex>
- XIU2/Yuedu：`https://cdn.jsdelivr.net/gh/XIU2/Yuedu@master/shuyuan`（数组格式，可整份导入）

## 七、边界与限制

- 只支持 HTML 抓取，不支持 JS 渲染页、不支持 POST 接口、不支持加密接口；
- 目录 / 正文的**分页拼接要在书源里显式配规则**（`chapterUrl` 的 `{page}`、`chapterNext`、`contentNext`），
  引擎不会去猜站点的翻页规律；单章最多拼 10 页，目录最多翻 20 页；
- 不做 OCR、不做字体反爬还原；
- **不提供任何绕过付费墙、请求签名、验证码的方案**——这类站点请只接你有权访问的公开部分。
